## Возможности

- Аптайм за 30 дней по каждому серверу, флаги стран, общий простой.
- Детализация дня: график пинга (лог. шкала), периоды сбоев, статистика проверок.
- «Подтверждённый» расчёт простоя (одиночный блип не считается за целый интервал).
- 4 темы (светлая / тёмная / Claude / Claude Code), переключатель + по системной; плавные анимации, адаптив под мобильные.
- Своё название, лого и favicon; история в SQLite (лёгкая, авто-очистка).
- Анти-фингерпринт: рандомизация классов и маскировка Server-заголовка.
- Опциональный админ-режим со скрытым входом (Ctrl+Shift+L / `#admin`): ручная чистка дублей и тумблеры авточистки/антидребезга; без токена страница ничем не выдаёт админку.

## Установка

Нужны Ubuntu/Debian и root. Установщик сам поставит Docker при необходимости.

Образ собирается автоматически в GitHub Actions и публикуется в GHCR
(`ghcr.io/mrvibecodic/xray-checker-statuspage`), а сервер только **тянет готовый образ** — без
локальной сборки и без клонирования репозитория. Рабочую папку `/opt/xray-checker-statuspage`
и `data/` создаёт сам установщик; вручную создавать ничего не нужно.

> **Важно: отключите HWID у сервисного пользователя.** Учётка, чью ссылку подписки вы укажете
> в `SUBSCRIPTION_URL`, должна быть **без ограничения HWID** (лимита устройств). xray-checker
> отправляет собственные HWID-заголовки, и если на этом пользователе включён HWID, панель в ответ
> отдаёт заглушку вместо списка серверов, а чекер падает с ошибкой
> `Error initializing configuration: no valid proxy configurations found`. В карточке этого
> пользователя в панели выключите HWID (или заведите отдельного служебного юзера без лимита устройств).

### Вариант A. Чистый сервер (установщик сам поставит nginx + HTTPS)

```bash
curl -fsSL https://raw.githubusercontent.com/Mrvibecodic/xray-checker-statuspage/main/install.sh -o install.sh
sudo bash install.sh
```

На вопрос про nginx отвечаешь «да» и вводишь домен. nginx ставится из официального
репозитория **nginx.org** (только если его ещё нет). Сертификат HTTPS обязателен, на выбор:

- **HTTP-01** — проверка по 80 порту (порт открыт извне);
- **Cloudflare DNS** — без открытия порта; API Token (`Zone.DNS: Edit`) или Global API Key + email.

### Вариант B. Сервер с панелью или уже установленным nginx

На вопрос про nginx отвечаешь «нет» — сервис поднимется на `http://127.0.0.1:8080`, проксирует панель/твой nginx.

```bash

          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }
  ```

  ```bash

  nginx -t && systemctl reload nginx
  certbot --nginx -d status.your-domain.example
  ```

```bash
cd /opt/xray-checker-statuspage && docker compose pull && docker compose up -d
```

Либо повторно `sudo bash install.sh` → «не перенастраивать»: обновит образ и перезапустит, настройки сохранятся.

## Обновление подписки (новый сервер)

Вручную ничего не нужно. xray-checker перечитывает подписку каждые `SUBSCRIPTION_UPDATE_INTERVAL`
секунд (по умолчанию 300), страница подхватывает новые серверы за пару минут; история нового
сервера копится с момента появления. Убранный из подписки сервер сам пропадёт.

Если сменил саму ссылку подписки — поправь `SUBSCRIPTION_URL` в `docker-compose.yml` и `docker compose up -d`.

## Кастомизация

Переменные окружения в `docker-compose.yml`. После правки — `docker compose up -d`.

Сервис `statuspage`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TITLE` | `Статус серверов` | заголовок в шапке и во вкладке |
| `SUBTITLE` | — | подзаголовок |
| `TZ` | `Europe/Moscow` | часовой пояс дат |
| `DAYS` | `30` | сколько дней истории показывать |
| `POLL_INTERVAL` | `300` | период опроса checker, сек (= `PROXY_CHECK_INTERVAL`) |
| `SAMPLE_RETAIN_DAYS` | `DAYS+1` | сколько дней хранить поминутные данные |
| `SERVER_HEADER` | `nginx` | значение заголовка `Server` (маскировка) |
| `CHECKER_URL` | `http://xray-checker:2112` | адрес xray-checker |
| `DB_PATH` | `/data/status.db` | путь к базе |
| `ADMIN_TOKEN` | — | секрет для админ-режима (ручное удаление записей со страницы). Пусто — выключено. **Минимум 48 символов** (короче — админка не включится). Сгенерировать: `openssl rand -hex 24`. |
| `STALE_AFTER_HOURS` | `0` | авто-**удаление из базы** записей, которые чекер перестал отдавать, через N часов. По умолчанию `0` — **выключено**: данные не трогаются, отсутствующие просто скрываются со страницы. `>0` — включить авто-purge. |
| `GLOBAL_OUTAGE_RATIO` | `1.0` | если в одном опросе доля офлайн-прокси ≥ этого порога — цикл считается возможным сбоем чекера и проходит подтверждение следующим циклом (см. ниже). `2` — отключить. |

Сервис `xray-checker` (основные):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SUBSCRIPTION_URL` | — | ссылка на подписку (можно несколько через запятую) |
| `PROXY_CHECK_INTERVAL` | `300` | как часто тестируются прокси, сек |
| `PROXY_TIMEOUT` | `30` | таймаут одной проверки, сек |
| `PROXY_CHECK_METHOD` | `ip` | метод: `ip`, `status` (легче), `download` |

### Тема

Кнопка в шапке циклирует между четырьмя темами:

- **светлая** — нейтрально-холодная палитра по умолчанию;
- **тёмная** — традиционный тёмный режим;
- **Claude** — тёплая кремовая палитра (`#F0EEE6` фон, `#FAF9F5` карточки) с
  фирменным copper-оранжевым акцентом `#D97757` — в духе brand-кода Anthropic;
- **Claude Code** — тёплая тёмная палитра (`#1A1815` фон, `#262320` карточки)
  с тем же copper-оранжевым — CLI-вайб Claude Code.

Иконка кнопки показывает следующую тему в цикле (луна → искра → `>_` → солнце →…).
Выбор сохраняется в `localStorage`. При первом заходе используется тёмная/светлая по
системной настройке. Цвета простоя на барах не привязаны к теме: зелёный (нет сбоев),
жёлтый (до 30 мин), оранжевый (30 мин – 2 ч), красный (от 2 ч).

### Группировка sub-серверов по имени хоста

xray-checker идентифицирует каждый прокси-конфиг отдельным `stableId`. Один логический
хост в подписке может быть представлен несколькими sub-серверами — например, когда внутри
хоста работает роутинг между несколькими апстримами. xray-checker опрашивает каждый
sub-сервер по очереди: пока один активен в роутинге и отвечает «online», остальные
выглядят «offline». На странице это выглядело как куча дублей одного хоста с дырявыми
аптайм-барами.

`statuspage` теперь группирует `current` по raw `name`:

- Все sid'ы с одинаковым именем показываются **одной** строкой.
- Текущий статус группы — по самому свежему `ts` (последний реально опрошенный sub-сервер).
- 30-дневный аптайм считается по «циклам опроса»: `cycles = sum(up+down) / n_members`,
  `up_cycles = min(sum_up, cycles)`. Для альтернирующего роутинга это даёт корректные
  100%, когда хост по факту всегда был доступен.
- График пинга внутри строки сливает samples всех членов группы: при совпадении ts
  «любой online → группа online», латентность = минимум среди online-членов.
- Админ-удаление (×) сносит **всю группу** целиком (иначе остались бы полу-призраки).

API-поле `members` в `/api/summary` показывает, сколько sub-серверов скрыто за строкой
(`members: 1` — обычный одиночный хост; `members: 2+` — группа). Фронт это показывает в
тексте подтверждения удаления.

### Глобальные сбои чекера (подтверждение, а не отбрасывание)

xray-checker иногда отдаёт `online: false` сразу по **всем** прокси — в моменты своего
рестарта, сетевого сбоя или перечитывания подписки. Географически разнесённые серверы не
могут отказать в одну и ту же секунду, так что «офлайн все разом» — почти всегда артефакт
самого чекера, а не реальный простой.

Чтобы такой блип не портил статистику и при этом **настоящий** тотальный отказ не терялся:

- Запрос к чекеру идёт с **ретраем** (3 попытки) — кратковременная недоступность самого
  чекера не превращается в ложный «все офлайн».
- Цикл, где офлайн ≥ `GLOBAL_OUTAGE_RATIO` прокси (по умолчанию `1.0` — все), **не пишется
  сразу**, а ждёт подтверждения: если **следующий** цикл снова «все офлайн» — это
  записывается как реальный простой; если ожило — разовый блип отбрасывается. Так транзиент
  не копит ложный простой, а длящийся отказ фиксируется (с задержкой в один цикл). В лог
  идёт `global-outage: …` (ждём подтверждения) или `global-outage подтверждён …`.
- Работает только при ≥ 2 прокси (на одиночном сервере глобальный сбой не отличить от
  реального). `GLOBAL_OUTAGE_RATIO=2` — выключить (писать всё сразу).
- В **админ-режиме** над списком есть переключатель «**Подтверждать глобальные сбои чекера
  (антидребезг)**» — включает/выключает это поведение на лету. Состояние в SQLite
  (`settings`), переживает рестарт. При `GLOBAL_OUTAGE_RATIO>1` тогл показан, но недоступен.

### Исчезновение убранных серверов

xray-checker отдаёт полный список серверов из подписки при каждом опросе. Если ты убрал
сервер из подписки (или сменил конфиг — у хоста меняется `stableId`), чекер перестаёт его
возвращать, и такой сервер **сам пропадает со страницы** на следующем же опросе — вручную
удалять не нужно. Его данные при этом **остаются в базе**: вернётся в подписку — строка
всплывёт обратно со всей историей. Новый сервер, наоборот, появляется сразу, как только
чекер его вернул.

В админ-режиме «отсутствующие в чекере» можно посмотреть (тумблер «**Показать отсутствующие
в чекере**») — они показаны серыми, и для них есть кнопка «**Удалить из базы**», если хочешь
стереть историю окончательно.

**Авто-удаление из базы по таймеру** (`STALE_AFTER_HOURS`) по умолчанию **выключено** (`0`) —
само ничего не стирается. Если поставить `>0`, `statuspage` будет раз в опрос удалять из
`current`/`daily`/`samples` группы, не приходившие дольше этого срока (сносится только если
**вся группа** с одним `name` старше порога — альтернирующий роутинг не задевается). В
админ-режиме есть тумблер «**Авто-удаление устаревших записей**» (состояние в SQLite,
переживает рестарт); при `STALE_AFTER_HOURS=0` он показан, но недоступен.

### Скрытие и удаление записей (админ-режим)

Узлы, которых больше нет в чекере, **сами пропадают** со страницы (см. раздел выше) — вручную
ничего делать не нужно. Админ-режим нужен для двух вещей: **скрыть** живой сервер от
пользователей (служебный конфиг) и **окончательно стереть** историю отсутствующего/скрытого
узла из базы. Для входа:

1. Нужен **`ADMIN_TOKEN`** для входа в админ-режим:

   - **Через install.sh** — токен генерируется автоматически при первой установке.
     Подсмотри его в `/opt/xray-checker-statuspage/.install-info` (строка
     «Админ-токен …»). На повторной установке (или при `sudo bash install.sh` поверх
     существующего) скрипт спросит, добавить ли токен, если его ещё нет.
   - **Вручную** — добавь в `docker-compose.yml` в секцию `statuspage`:

     ```yaml
     statuspage:
       environment:
         - ADMIN_TOKEN=<сгенерируй-командой-ниже>
     ```

     Токен — **не короче 48 символов** (иначе админка не включится). Сгенерировать:
     `openssl rand -hex 24`. Затем `docker compose up -d`.

2. Открой страницу и вызови вход **скрытым жестом** (видимой кнопки-замка на странице нет):
   нажми **Ctrl+Shift+L** или открой адрес с якорем **`#admin`** (`https://домен/#admin`).
   Появится поле ввода токена. Токен запомнится в `localStorage`; повторный ввод не нужен.

3. В режиме админа в шапке показывается замок (для выхода), а у строк появляются действия:
   - **× «Скрыть»** на обычной строке — убирает сервер с публичной страницы (для служебных
     конфигов, которые есть в чекере, но не нужны пользователям). Строка становится серой с
     пометкой «скрыто», данные продолжают копиться — обратимо.
   - На скрытой строке: **«Вернуть на страницу»** и **«Удалить из базы»** (стереть историю из
     `current`/`daily`/`samples`).
   - На строке «**нет в чекере**» (узел убран из подписки; видна по тумблеру «Показать
     отсутствующие») — **«Удалить из базы»**.

   Скрытие мягкое и обратимое; удаление из базы — осознанное и необратимое (откат только из
   бэкапа `data/status.db`).

Чтобы выйти из админ-режима — снова **Ctrl+Shift+L** или клик по замку.

> **Если сервер вернётся после удаления** — значит, он всё ещё есть в подписке, которую
> опрашивает xray-checker, и следующий же опрос его снова добавит. Удалять нужно именно
> *старые `stableId`*, которые уже не приходят из чекера; новые активные сервера будут
> возвращаться, и это нормально.

Если `ADMIN_TOKEN` не задан, короче 48 символов или неверный — админ-режим недоступен никому,
а запросы к админ-ручкам (`/api/admin/*`) неотличимы от несуществующих путей (обычный `404`).
Снаружи страница выглядит как рядовой публичный статус-пейдж: что админка вообще есть, нигде
не афишируется. Это безопасное состояние по умолчанию.

## Частота опроса

Уменьшай оба интервала и держи равными:

```yaml
  xray-checker:
    environment:
      - PROXY_CHECK_INTERVAL=60
  statuspage:
    environment:
      - POLL_INTERVAL=60
```

`PROXY_CHECK_INTERVAL` > `PROXY_TIMEOUT` (проверки параллельны; при таймауте 30 сек минимум ~40–60 сек).
Практический минимум — 30–60 сек.

## Как считается простой

Простой считается только по подряд идущим неудачным проверкам: 1 сбой → 0 (блип), 2 подряд → 1
интервал, 3 → 2 и т.д. Процент аптайма учитывает все проверки, поэтому блип виден в проценте и
в подсказке как «кратковременный сбой».

## Нагрузка на SQLite

Дневные агрегаты (крошечные) + поминутные замеры за `SAMPLE_RETAIN_DAYS` дней (~70 байт/замер).
При 31 дне:

| Серверов | 60с | 30с | 15с | 10с |
|---|---|---|---|---|
| 10 | ~31 МБ | ~62 МБ | ~125 МБ | ~187 МБ |
| 25 | ~78 МБ | ~156 МБ | ~312 МБ | ~470 МБ |
| 50 | ~156 МБ | ~312 МБ | ~625 МБ | ~940 МБ |
| 100 | ~312 МБ | ~625 МБ | ~1.25 ГБ | ~1.9 ГБ |

Упирается в место на диске, не в производительность (выборка по индексу быстра). Для экономии —
меньше `SAMPLE_RETAIN_DAYS` (30-дневная шкала аптайма не пострадает).
